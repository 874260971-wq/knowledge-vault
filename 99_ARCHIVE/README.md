# 🗃 99 · 归档区 / Archive

> **冷存储。** 过期素材、不再用的旧方法、失败的案例,放进这里。
> 保留是为了将来的"将来"。不要清空,但也不要让它出现在前面。

## 📂 子目录

| 目录 | 内容 |
|---|---|
| `99_ARCHIVE/Inbox-过期/` | 7 天没处理完的 Inbox |
| `99_ARCHIVE/方法库-弃用/` | 已被新方法取代的旧方法 |
| `99_ARCHIVE/选题-过期/` | 时效已过的选题 |
| `99_ARCHIVE/案例-过期/` | 失去当下借鉴价值的案例 |
| `99_ARCHIVE/内容-下架/` | 已删除 / 平台下架 / 失败不再维护 |

## 🎯 归档的意义

- 不删除(可能某天又用得着)
- 不让它们出现在日常检索结果中
- 半年一次的复盘可以"复活"对的内容

## 📌 触发归档

| 触发 | 动作 |
|---|---|
| Inbox 里 7 天没动过 | 移到 `99_ARCHIVE/Inbox-过期/` + 加 `⚠️ 7-day-not-touched` 标记 |
| 方法被新版本取代 | 在 [[../../06_SYSTEM/禁忌清单]] 加一条 + 文件移到 `方法库-弃用/` |
| 选题过了时效(>3 个月没复用) | 移到 `选题-过期/` |
| 案例过了 6 个月且新案例更有说服力 | 移到 `案例-过期/` |
| 发布的内容被平台下架 | 文件名前加 `下架-`,文件移到 `内容-下架/` |

## 📊 半年一次"复活"检查

每 6 个月做一次:
- 翻 `选题-过期/` → 是否能改成新选题?
- 翻 `案例-过期/` → 是否能重新包装?
- 翻 `方法库-弃用/` → 是否值得修?

## 命名规范

`YYYY-MM-DD_<原文件名>.md`
加 frontmatter:

```yaml
---
原位置: <路径>
归档原因:
归档日期:
状态: 归档 / 复活 / 删除
---
```
